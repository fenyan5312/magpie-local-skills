# 进度计算、休息提醒与自迭代

## 数据目录

```text
专升本备考/
  配置/学习配置.yaml
  学科/<学科>/
    00_考纲/
    01_计划/
    02_学习记录/
    03_错题/
    04_复盘/

  进度/YYYY-MM-DD.json
  考纲缓存/YYYY-<学科>/evidence.json

```

只有用户明确提供学科名称后才创建具体学科目录；不要一次性虚构所有学科。

## 计算规则

- 完成率按 `实际分钟 / 计划分钟` 和 `完成任务数 / 计划任务数` 分开计算；计划为 0 时不报无穷大，标记为“无计划”。
- 欠账 = 截至本次节点未通过验收的任务；超前 = 已完成且通过验收、但尚未到计划时间的任务。
- 每次对齐都要同时给出绝对差额（分钟、任务数）和相对差额（%），不能只给百分比。
- 连续未完成天数按每人独立统计；任何一人连续 2 天完成率低于 70%，提醒优先修复任务量和睡眠，不直接堆更多内容。

## 休息判断

- 连续 2 天完成率 >= 120%，或当天实际量 >= 计划量 130%：提出最近 1-2 天内的轻量放松日，保留错题回炉、单词/公式等低强度复习。
- 没有超前、但疲劳感高且欠账超过 20%：降低当日新任务量，保留一个最小闭环，不建议完全放空。
- 超前不等于永久加码；连续 3 天超前后必须检查计划是否过低或任务验收是否过松。

## 自迭代闭环

每次运行结束，向 `迭代/记录.md` 追加一节：

```markdown
## YYYY-MM-DD HH:MM · 运行记录
- 输入：考纲年份、当前颗粒度、本次节点。
- 观察：实际数据、用户反馈、生成失败或偏差。
- 假设：当前规则为什么有效/失效。
- 改动：配置、目录、模板或 skill 的具体变更。
- 验证：用真实数据重新生成/计算，结果是否符合预期。
- 回滚：上一版本位置或恢复方式。
```

只有“观察 + 改动 + 验证”齐全时才改规则；单纯一次措辞不喜欢，只改消息模板。每次改动都记录旧值和新值，避免把临时补丁堆成不可解释的规则。
