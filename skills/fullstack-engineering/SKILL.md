# Full-stack Engineering

Own the feature across boundaries. Map architecture, data flow, deployment assumptions, and test strategy before editing.

Define contracts, invariants, authorization, failure semantics, and compatibility. Validate untrusted input at boundaries; keep domain rules in services rather than controllers or UI. Keep API errors consistent without leaking internals. Keep database access explicit and testable; avoid N+1 and over-fetching. Update types, migrations, fixtures, docs, and tests together when contracts change.

Cover happy path, invalid input, unauthorized/forbidden, not-found, conflict, retry/idempotency, and persistence failure as applicable. Run formatter/linter, unit, API/integration, and browser tests; review security, races, compatibility, and operational failure modes.
