# Product PRD

Start with user problem and desired outcome, not a feature list. Identify target users, context, pain, workaround, and why now. Define measurable outcome metrics and output metrics separately. Map primary and edge journeys, roles/permissions, states, dependencies, and recovery. Separate must-have scope, non-goals, later phases, and open decisions. Specify UX, data/API implications, analytics, accessibility, security, and operations. Convert requirements into testable acceptance criteria and flag assumptions and risks.

Use: summary, problem, users, goals/non-goals, journeys, requirements, states, acceptance criteria, metrics, dependencies, rollout/rollback, risks, open questions. Keep language concrete and avoid prescribing implementation before constraints are understood.
