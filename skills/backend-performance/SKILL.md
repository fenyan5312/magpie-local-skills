# Backend Performance

Optimize evidence-first. Establish symptom and target (latency percentile, throughput, errors, memory, CPU, query time, or cost) before changing code.

Reproduce or inspect traces, metrics, logs, profiles, and representative workloads. Locate bottlenecks across network, serialization, application, external calls, pools, cache, and database. Choose the least risky fix: query/index shape, batching, pagination, N+1 removal, bounded cache, async work, pool tuning, payload reduction, or algorithmic improvement. Consider concurrency, staleness, retries, timeouts, cancellation, backpressure, and partial failure. Benchmark before/after and document trade-offs and rollback. Never add caching, retries, parallelism, or indexes blindly.
